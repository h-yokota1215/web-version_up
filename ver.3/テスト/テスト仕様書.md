# ver.3 テスト仕様書

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| 対象システム | 受注管理システム |
| 対象バージョン | ver.3 |
| 基準バージョン | ver.2（`juchu02`） |
| 文書名 | テスト仕様書 |
| ファイル名 | `テスト仕様書.md` |
| 参照資料 | 要求分析書、仕様書、基本設計書、DB設計書、詳細設計書 |
| テスト対象 | 個人顧客対応および既存法人顧客機能への影響 |
| 文書状態 | 初版案 |

## 2. テストの目的

ver.3で追加・変更する個人顧客登録、認証、受注、支払方法、与信判定および売掛残高管理が、仕様書および設計書で定義したとおりに動作することを確認する。

また、個人顧客対応の追加によって、既存の法人顧客向け機能に不具合が発生していないことを確認する。

## 3. テスト対象範囲

### 3.1 テスト対象機能

| 機能ID | 機能名 | 主な確認内容 |
|---|---|---|
| F-01 | 個人顧客登録 | 入力チェック、顧客情報・認証情報の登録、採番 |
| F-02 | 個人顧客情報参照 | 個人顧客テーブルからの情報取得 |
| F-03 | 個人顧客認証 | 個人顧客の認証および顧客種別判定 |
| F-04 | 商品選択 | 個人顧客による既存商品検索・選択 |
| F-05 | 受注登録 | 個人顧客の受注情報・受注明細の登録 |
| F-06 | 支払方法選択 | 顧客種別に応じた支払方法の表示・保存 |
| F-07 | 与信・売掛残高管理 | 支払方法に応じた与信判定・残高更新 |
| F-08 | 法人顧客機能の維持 | 既存機能の回帰確認 |

### 3.2 テスト対象外

以下はver.3の仕様対象外であるため、本テストでは確認しない。

- 外部決済サービスとの連携
- 代金引換に関する配送業者との連携
- 銀行振込の入金消込処理
- 商品マスタ・商品検索機能の全面的な再設計
- 受注業務構造の全面的な変更
- 要求資料に記載されていない新規業務機能

## 4. テスト実施方針

### 4.1 テスト区分

| テスト区分 | 確認内容 |
|---|---|
| データベース確認 | テーブル定義、初期データ、NULL、採番管理情報 |
| 登録テスト | 個人顧客情報・認証情報の登録、入力チェック |
| 認証テスト | 顧客コード・パスワードによる認証 |
| 画面・業務テスト | 商品選択、支払方法選択、受注処理 |
| 与信・残高テスト | 与信判定、売掛残高更新、更新先 |
| 回帰テスト | 法人顧客の既存機能への影響 |

### 4.2 判定基準

- 期待結果と実際の結果が一致した場合は「OK」とする。
- 期待結果と異なる場合は「NG」とし、現象・発生条件を記録する。
- テストを実施できない場合は「未実施」とし、OKとして扱わない。
- 不具合修正後は、該当テストおよび関連する回帰テストを再実施する。

## 5. テストデータ・実施前提

### 5.1 個人顧客サンプルデータ

個人顧客の初期データ4件を利用する。

| 顧客コード | 顧客名 | 営業所コード | 与信限度額 |
|---|---|---|---:|
| 400000 | 山田太郎 | 01 | 1,000,000円 |
| 400001 | 山田花子 | 02 | 1,000,000円 |
| 400002 | 鈴木一郎 | 03 | 1,000,000円 |
| 400003 | 花山治郎 | 03 | 1,000,000円 |

認証テストでは、初期データに登録された認証情報を利用する。

### 5.2 新規登録用テストデータ

新規登録テストでは、既存データと重複しない顧客情報を使用する。

メールアドレス重複テストでは、次の組み合わせを用意する。

- 既存個人顧客と同じメールアドレスを使用する個人顧客
- 既存法人顧客と同じメールアドレスを使用する個人顧客
- 既存法人顧客と同じメールアドレスを使用する法人顧客

法人顧客同士のメールアドレス重複チェックは既存仕様を維持する。

### 5.3 受注・与信テストデータ

与信テストでは、個人顧客の売掛残高と与信限度額を確認できる状態にする。

銀行振込の与信判定では、次の条件を用意する。

- 売掛残高と今回受注額の合計が与信限度額未満となる条件
- 合計が与信限度額と一致する条件
- 合計が与信限度額を超過する条件

与信テストの前後で、対象顧客の売掛残高および法人顧客の売掛残高を確認する。
