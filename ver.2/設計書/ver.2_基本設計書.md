# juchu01 ver.2 基本設計書

## 0. 開発対象と基準環境

- 基準：`juchu01`、DB `COSCOMMON01`。変更しない。
- 開発対象：`juchu02`、DB `COSCOMMON02`。設計完了後に`juchu01`をコピーして作成する。
- コンテキスト・ルート：`juchu02`。
- 画面・ソースの配置は、コピー元の`juchu01`構成を維持する。

### バージョン別プロジェクト・DB分離方針

改修バージョンごとにプロジェクトフォルダーとH2データベースを分離する。各バージョンは直前バージョンの完成状態をコピーして開始し、過去バージョンは変更しない。

| バージョン | プロジェクトフォルダー | コンテキスト・ルート | H2 DB |
|---|---|---|---|
| Ver.1（基準） | `juchu01` | `juchu01` | `COSCOMMON01` |
| Ver.2 | `juchu02` | `juchu02` | `COSCOMMON02` |
| Ver.3 | `juchu03` | `juchu03` | `COSCOMMON03` |
| Ver.4 | `juchu04` | `juchu04` | `COSCOMMON04` |
| Ver.5 | `juchu05` | `juchu05` | `COSCOMMON05` |

作成手順は、`juchu01`を基準として`juchu02`を作成し、ver.2完了後に`juchu02`をコピーして`juchu03`を作成する。その後も同様に、`juchu03`から`juchu04`、`juchu04`から`juchu05`を作成する。DBも同じ対応関係で新規作成し、各バージョンのCREATE・INSERT・テストデータを混在させない。

## 1. 設計目的

食品、AV機器、PCを既存の商品検索・詳細・カート・受注の流れへ追加する。既存の文具・書籍機能は維持し、商品共通情報とカテゴリ固有情報を分離して扱う。

## 2. 設計方針

| 方針 | 内容 |
|---|---|
| DB構成 | 既存のカテゴリ別商品テーブル方式を踏襲し、`FOODS_TABLE`、`AV_TABLE`、`PC_TABLE`を追加する |
| 共通モデル | `Shohin`を継承し、共通項目・在庫情報・カテゴリ情報を再利用する |
| 固有モデル | `Foods`、`Av`、`Pc`を追加し、カテゴリ固有項目を保持する |
| カテゴリ判定 | 商品コード先頭2桁を使用する。`03`食品、`04`AV機器、`05`PC |
| サブカテゴリ判定 | 商品コード先頭4桁を使用する |
| 一覧取得 | 現行`DaoShohin`のカテゴリテーブル名取得方式を拡張する |
| 詳細取得 | `DaoFoods`、`DaoAv`、`DaoPc`を追加し、商品コードから詳細を取得する |
| 画面 | 既存の`WebContent`直下JSP配置、画面命名、遷移方式を踏襲し、カテゴリ別詳細JSPを追加する |
| 画像 | Excelの画像URIを`WebContent/img`配下と一致させる |
| 回帰 | 文具・書籍の検索、詳細、カート、受注を改修前と同じ結果で確認する |

## 3. 対象範囲

### 対象

- 商品カテゴリ・サブカテゴリの登録
- 商品テーブル、メーカー、営業所別在庫の登録
- 商品共通モデルとカテゴリ固有モデル
- 商品一覧、商品詳細、画像表示
- カート追加、在庫確認、受注登録への新商品対応
- ver.2のテスト仕様・作業報告

### 対象外

- 個人顧客対応（ver.3）
- 受注割引（ver.4）
- SQLインジェクション対策（ver.5）

## 4. 構成変更の概要

```text
カテゴリ選択
  -> JuchuControl
  -> ShohinControl
  -> DaoControl / DaoShohin
  -> CTR_GCTG_TABLE・GSUBCTG_TABLEからカテゴリ判定
  -> Foods / Av / Pc の商品テーブル
  -> 共通項目 + 固有項目 + 営業所別在庫
  -> 商品一覧・詳細・カート・受注
```

## 5. 設計上の重要な確認点

- 現行`DaoControl.selectShohin`は`01`と`02`しか詳細DAOへ振り分けないため、`03`～`05`を追加する。
- 現行`JuchuControl`は商品コード先頭2桁から`詳細01`・`詳細02`を作るため、同じ方式で`詳細03`～`詳細05`を追加する。
- 現行一覧取得は`CTR_GCTG_TABLE.CLASSNAME`からテーブル名を組み立てるため、`Foods_TABLE`等の命名とDB登録値を一致させる。
- `ShohinCategory`のコード抽出処理は商品コード仕様と照合し、設計上は先頭2桁・先頭4桁で統一する。
- 画像URIはExcelの値をそのまま利用できるよう、配置先とWebアプリの公開パスを統一する。
