# juchu01 ver.2 要求分析

## 1. 分析対象

- 要件資料：`../../改修要件/ver.2/改修要件2.pdf`
- サンプルデータ：`改修要件/ver.2/サンプルデータ/`
- 現行システム：`juchu01`
- 現行DB資料：`sql/create.sql`、`sql/insert.sql`、`juchu01_DB改修方針.md`

## 2. 要求の要約

ver.2の目的は、取扱商品を増やし、顧客満足度と新規顧客の拡大につなげることである。

| 要求ID | 要求 | 判定基準 |
|---|---|---|
| V2-R01 | 文具・書籍に加え、食品・AV機器・PCを商品カテゴリとして追加する | 5カテゴリがカテゴリ選択画面に表示される |
| V2-R02 | 商品一覧にはカテゴリ共通の項目を表示する | 新3カテゴリの商品一覧で共通項目が表示される |
| V2-R03 | 商品詳細には共通項目と商品固有項目を表示する | 食品・AV機器・PCそれぞれの固有項目が詳細画面に表示される |
| V2-R04 | サンプルデータを使用してテストする | サンプル商品・画像を登録し、検索から受注まで確認できる |

## 3. 現行機能との対応

### 3.1 現行の処理経路

1. `JuchuControl`が商品検索要求を受け取る。
2. `ShohinControl`を経由して`DaoControl.selectShohin`を呼び出す。
3. サブカテゴリコードの場合は`DaoShohin`、商品コードの場合はカテゴリ別DAOを使用する。
4. `DaoShohin`が共通項目を取得し、カテゴリ別DAOが固有項目を取得する。
5. `Shohin`派生クラスをセッションへ格納し、一覧・詳細JSPで表示する。

### 3.2 改修が必要な主な箇所

| 層 | 現行 | ver.2で必要な対応 |
|---|---|---|
| DBカテゴリ | `CTR_GCTG_TABLE`は文具・書籍のみ | 食品・AV機器・PCを追加 |
| DBサブカテゴリ | `GSUBCTG_TABLE`に既存2カテゴリのデータ | 新3カテゴリのサブカテゴリを追加 |
| DB商品 | `BUNGU_TABLE`、`BOOK_TABLE` | `FOODS_TABLE`、`AV_TABLE`、`PC_TABLE`を追加する方針 |
| DB在庫 | `HANBAIZAIKO01～03_TABLE` | 新商品を営業所別在庫へ追加 |
| Javaモデル | `Shohin`、`Bungu`、`Book` | `Foods`、`Av`、`Pc`を追加 |
| Java DAO | `DaoShohin`、`DaoBungu`、`DaoBook` | 新3カテゴリのDAOと検索・詳細取得を追加 |
| DAO振り分け | `DaoControl`がコード`01`・`02`のみ判定 | `03`・`04`・`05`を判定対象に追加 |
| 詳細画面 | `cosd1040.jsp`、`cosd1041.jsp` | 既存方式を維持し、`cosd1042.jsp`～`cosd1044.jsp`を追加 |
| ルーティング | `JuchuControl`が商品コード先頭2桁で詳細画面を決定 | 新カテゴリの詳細画面遷移を追加 |
| 画像 | 商品の`IMG_URI`を参照 | サンプル画像を`WebContent/img`へ配置しURIを整合 |

## 4. データ・画面要求の整理

### 4.1 共通項目

現行の`Shohin`および既存商品テーブルを基準とし、少なくとも次の項目を全カテゴリで扱う。

- 商品コード
- 商品名
- 標準単価
- 入数
- 単位
- メーカー
- コメント
- 画像URI
- 商品種別
- 営業所別在庫数
- 引当可能数・在庫表示

### 4.2 固有項目

食品・AV機器・PCの固有項目は、サンプルデータの項目定義を確認して確定する。現行の`Bungu`・`Book`と同様に、`Shohin`を継承するカテゴリ別モデルへ保持する。

### 4.3 一覧表示

- 既存の文具・書籍と同じ検索導線で新カテゴリを検索できること。
- 共通項目を一覧に表示すること。
- 数量入力、詳細表示、カート追加が既存商品と同じ流れで行えること。
- 営業所ごとの在庫表示が既存仕様と同じ判定で行われること。

### 4.4 詳細表示

- 共通項目を表示すること。
- カテゴリ固有項目を表示すること。
- 商品画像を表示すること。
- 詳細画面からカート追加へ遷移できること。

## 5. サンプルデータ確認結果

`サンプルデータ.xlsx`には、ver.2で使用する商品データが格納されている。シート構成は次のとおりである。

| データ | 内容 |
|---|---|
| 商品カテゴリ | 食品、AV機器、PC。カテゴリコードは`03`、`04`、`05`、クラス名は`Foods`、`Av`、`Pc` |
| サブカテゴリ | `301`食品、`302`飲料、`303`健康食品／サプリメント、`401`テレビ、`402`ビデオレコーダー、`403`プロジェクタ、`404`オーディオプレイヤー／コンポ、`405`その他OA機器、`501`PC |
| 商品データ | 食品4件、AV機器4件、PC3件 |
| 在庫データ | 3営業所分、商品コード・実在庫数・引当数など |
| 画像 | `img/foods`、`img/av`、`img/pc`に商品画像 |

### 5.1 共通項目

商品データには、商品コード、商品名、入数、単位、販売単価、メーカーコード、商品コメント、商品写真、商品種別が含まれる。

### 5.2 固有項目

| カテゴリ | 固有項目 |
|---|---|
| 食品 | 味、内容量、製造国、熱量、原材料、栄養成分、その他 |
| AV機器 | 色、型番、画面サイズ、画面解像度、出力音量、記憶容量、対応メディア、インターフェース、消費電力、付属品、保証期間、質量、寸法、その他 |
| PC | 色、型番、画面サイズ、画面解像度、CPU、メモリ容量、HDD容量、ドライブ、ネットワーク、OS、統合ソフト、バッテリ、付属品、保証期間、質量、寸法、その他 |

### 5.3 確認済みの改修前提

- 商品コードの先頭2桁でカテゴリを判定する。`03`は食品、`04`はAV機器、`05`はPCである。
- 商品コードの先頭4桁でサブカテゴリを判定する。
- 営業所コード`01`～`03`の在庫データを登録する。
- 商品写真の値は、`WebContent/img`配下の配置先に合わせて登録する。

## 7. 要求から設計への引継ぎ事項

### DB設計

- 新3カテゴリの固有テーブルを既存テーブルと同じ共通項目構成で設計する。
- `CTR_GCTG_TABLE`、`GSUBCTG_TABLE`、メーカー、在庫、商品テーブルの登録順を整理する。
- 商品コードの一意性とカテゴリコードの整合性を確認する。

### Java設計

- `Shohin`の共通項目は原則再利用する。
- カテゴリ固有項目は`Foods`、`Av`、`Pc`へ分離する。
- DAOのカテゴリ判定処理と詳細画面へのルーティングを拡張する。
- 商品コードの桁数・カテゴリ抽出ロジックを設計書と照合する。

### テスト設計

- `juchu01_テスト仕様書.md`のV2項目を、固有項目・画像・在庫・受注DB確認まで具体化する。
- 新カテゴリ3種について、一覧・詳細・カート・在庫・受注の正常系を準備する。
- 未登録カテゴリ、存在しない商品コード、画像未配置、在庫不足を異常系として確認する。
- 文具・書籍の回帰テストを必須とする。

## 8. 要求分析の結論

要求の中心は「カテゴリ追加」だけではなく、商品モデル、DAO、DB、画面、画像、在庫、受注処理を一貫して新カテゴリへ対応させることである。

ver.2のExcelから商品項目、カテゴリコード、サブカテゴリ、クラス名、在庫データを確認し、DB列・Javaフィールド・画面項目への割り当て、実装、テストまで完了した。
