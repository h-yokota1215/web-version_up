# juchu01 ver.2 開発フォルダー

ver.2の要求分析、設計、テスト設計、作業記録をまとめるフォルダーである。

## 開発対象

- 基準プロジェクト：`juchu01`（Ver.1。変更禁止）
- ver.2開発プロジェクト：`juchu02`（設計完了後に`juchu01`をコピーして作成）
- ver.2 DB：H2 `COSCOMMON02`
- コンテキスト・ルート：`juchu02`
- SQL：`sql/ver.2/create.sql`、`sql/ver.2/insert.sql`、`sql/ver.2/select.sql`

`juchu02`作成前は、`juchu01`のソース・JSP・設定を変更しない。

## 後続バージョンの分離

ver.2以降も同じ規則で、バージョンごとに新しいプロジェクトフォルダーとDBを作成する。

| バージョン | フォルダー | DB |
|---|---|---|
| ver.3 | `juchu03` | `COSCOMMON03` |
| ver.4 | `juchu04` | `COSCOMMON04` |
| ver.5 | `juchu05` | `COSCOMMON05` |

後続版は直前版をコピーして作成し、過去版の成果物は変更しない。

## ファイル構成

| ファイル | 内容 |
|---|---|
| `juchu01_ver2要求分析.md` | 要求、現行影響、未確定事項の整理 |
| `ver.2_基本設計書.md` | 改修方式、構成、画面・DB・クラスの基本方針 |
| `ver.2_詳細設計書.md` | テーブル、クラス、DAO、画面、処理フローの詳細 |
| `ver.2_テスト仕様追補.md` | ver.2固有のテストデータと確認項目 |
| `ver.2_作業・振り返り.md` | 設計判断、実装結果、課題、振り返りの記録 |
| `ver.2_設計レビュー.md` | 設計不足・矛盾・実装結果・レビュー指摘の管理 |
| `ver.2_変更対象一覧.md` | Java・JSP・HTML・SQLの変更対象とコメントルール |
| `ver.2_設計完了チェックリスト.md` | 設計・実装・テスト完了確認 |

DBの物理設計表は`ver.2/設計/DB設計/ver.2_DB物理設計書.md`に記載する。

基準版`juchu01`から引き継いだ未登録コード空レスポンスは、ルート直下の`juchu01_既存不具合報告_未登録コード空レスポンス.md`で別管理する。

## 報告資料

- ルート直下の`ver.2_テスト報告書.pptx`：テスト報告書（ひな形準拠）
- ルート直下の`ver.2_テスト報告書_改訂版.pptx`：テスト項目・テスト結果を追記した改訂版
- ルート直下の`ver.2_テスト結果一覧.xlsx`：テスト項目・実施結果・判定の添付用一覧
- ルート直下の`ver.2_テスト結果一覧_修正版.xlsx`：Excel読込エラー対応版
- `ver.2/報告書/ver.2_改修概要.md`：報告用の改修概要
- `ver.2/報告書/ver.2_改修詳細.md`：報告用の改修詳細

## 開発時の更新順

1. 要求分析の未確定事項を解消する。
2. 基本設計・詳細設計を更新する。
3. テスト仕様追補へ入力値と期待結果を追加する。
4. 実装前に設計書とテスト仕様をレビューする。
5. 実装・テストの結果を作業・振り返りへ記録する。
6. 完了後に成果物を実際のフォルダー配置と照合し、READMEと相対リンクを更新する。
