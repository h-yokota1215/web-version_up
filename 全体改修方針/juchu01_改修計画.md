# juchu01 改修計画

## 1. 概要

既存の `juchu01` 受注システムに対して、ver.2～ver.5の改修を順番に実施する。

開発完了予定日は **2026年12月24日** とする。

## 2. 改修要件の要約

| Version | 改修内容 |
|---|---|
| ver.2 | 食品・AV機器・PCの商品カテゴリを追加し、一覧の共通項目と詳細の固有項目を表示する。 |
| ver.3 | 個人顧客の登録・受注機能を追加する。個人の支払方法は代金引換・口座振込とする。 |
| ver.4 | 受注単位の割引を追加する。法人は小計30万円以上で10%、個人は誕生日月日一致で50%とする。 |
| ver.5 | SQLインジェクションによる不正ログインを防止する。 |

### ver.3の補足

個人顧客コードの先頭1桁は4～8、個人顧客の与信限度額は100万円とする。

### ver.4の補足

割引後の金額を基に消費税と合計金額を計算する。

## 4. 開発の進め方

「システム設計実習ガイダンス.html」に従い、各バージョンを次の順序で進める。

1. 改修要件の分析

2. 基本設計・詳細設計

3. 実装

4. 単体テスト・結合テスト

5. 作業記録とテスト結果の整理

6. バージョン別報告書作成

7. レビューと指摘事項の反映

### 4.1 バージョン別プロジェクト・DB

各バージョンは独立したEclipseプロジェクトとH2データベースで管理する。直前バージョンをコピーして次のプロジェクトを作成し、過去バージョンは変更しない。

| バージョン | プロジェクト | コンテキスト・ルート | H2 DB |
|---|---|---|---|
| Ver.1 | `juchu01` | `juchu01` | `COSCOMMON01` |
| Ver.2 | `juchu02` | `juchu02` | `COSCOMMON02` |
| Ver.3 | `juchu03` | `juchu03` | `COSCOMMON03` |
| Ver.4 | `juchu04` | `juchu04` | `COSCOMMON04` |
| Ver.5 | `juchu05` | `juchu05` | `COSCOMMON05` |

ver.2は`juchu01`から`juchu02`を作成し、ver.3以降は直前バージョンから新しいフォルダーとDBを作成する。

ver.5完了後に、ver.2～ver.5の総合回帰テストと最終報告書作成を行う。

## 6. バージョン間の依存関係

- ver.2で追加する商品モデル・DAOを、ver.3以降の受注処理でも利用する。

- ver.3で追加する個人顧客情報を、ver.4の個人向け割引判定で利用する。

- ver.4で変更する金額計算を、ver.5の総合回帰テストで再確認する。

- ver.5ではログイン処理だけでなく、既存DAOのSQL生成処理も確認する。
