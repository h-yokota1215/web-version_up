# juchu01 テスト仕様書

## 1. 文書概要

本書は、juchu01の現行機能を正常な基準機能として扱い、ver.2～ver.5改修に対するテスト方針・テスト項目を定義する。

| 項目 | 内容 |
|---|---|
| 対象システム | juchu01 受注システム |
| DB | H2 `coscommon01` |
| Webサーバー | Tomcat 9 |
| Java | Java 11 |
| 文字コード | UTF-8 |
| 基準資料 | 改修要件2～5、システム設計実習ガイダンス |

## 2. テスト方針

- 改修前の既存機能が維持されることを回帰テストで確認する。

- 現行機能は改修前ベースラインとして、すべて正常に動作することを前提とする。

- 各バージョンの機能テスト後に、関連する全体機能を確認する。

- 正常系、異常系、境界値、DB更新結果を確認する。

- 画面表示だけでなく、DAOの検索・登録・更新結果を確認する。

- ver.5ではSQLインジェクション対策をセキュリティテストとして確認する。

## 3. テスト環境・初期データ

### 3.1 DB初期化

1. H2データベースを起動する。

2. `sql/create.sql`を実行する。

3. `sql/insert.sql`を実行する。

4. `sql/select.sql`で初期データを確認する。

5. テスト開始前に対象テーブルの件数と採番値を記録する。

### 3.2 主なテストデータ

| 種類 | データ |
|---|---|
| 法人顧客 | `100000`～`100003` |
| 法人パスワード | `pass0000`、`pass1111`等 |
| 商品カテゴリ | 文具、書籍 |
| 営業所 | `01` 大阪、`02` 東京、`03` 福岡 |
| 受注 | `1202000001` |

ver.2以降は、改修要件フォルダーのサンプルデータを追加して使用する。

## 4. テスト区分

| 区分 | 内容 |
|---|---|
| 単体テスト | クラス・メソッド・SQL単位の確認 |
| 結合テスト | Servlet、Control、DAO、DB、JSPの連携確認 |
| 機能テスト | 要件ごとの画面操作と結果確認 |
| 回帰テスト | 改修前から存在する機能の再確認 |
| セキュリティテスト | 不正入力・SQLインジェクション対策の確認 |

## 5. テスト結果の記録形式

| 項目 | 内容 |
|---|---|
| テストID | 一意のテスト識別子 |
| 対象バージョン | ver.2～ver.5 |
| テスト区分 | 単体・結合・機能・回帰・セキュリティ |
| 前提条件 | DB状態、ログイン状態など |
| 操作・入力 | 実施する操作と入力値 |
| 期待結果 | 画面、DB、ログの期待結果 |
| 実施結果 | 実際の結果 |
| 判定 | OK / NG |
| 備考 | 不具合ID、証跡など |

## 8. ver.3以降のテスト項目（予定）

### ver.3 個人顧客

- 個人顧客の登録、ログイン、受注ができること。

- 個人顧客コードの先頭が4～8になること。

- 与信限度額100万円が登録・判定に使用されること。

- 代金引換・口座振込を選択できること。

- 法人の受注処理に影響がないこと。

### ver.4 割引

- 法人の小計299,999円、300,000円、300,001円を確認すること。

- 個人の誕生日月日一致・不一致を確認すること。

- 小計、割引額、消費税、合計金額が正しいこと。

- 割引なしの受注が正しく登録されること。

### ver.5 SQLインジェクション対策

- 正常な認証情報でログインできること。

- 誤った認証情報でログインできないこと。

- SQLインジェクション文字列で認証を突破できないこと。

- 特殊文字、空文字、長大入力でSQLエラーが発生しないこと。

## 9. 不具合管理

不具合を検出した場合は、次の情報を記録する。

- 不具合ID

- 発見バージョン・発見日

- 再現手順

- 入力値・前提条件

- 期待結果と実際の結果

- 影響範囲

- 対応内容

- 修正後の再テスト結果

## 10. 報告書への反映

各バージョンの報告書には、対象バージョンのテスト項目、実施結果、未解決不具合、回帰テスト結果を反映する。

最終報告書には、ver.2～ver.5のテスト結果を統合して記載する。
